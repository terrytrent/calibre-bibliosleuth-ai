BiblioSleuth AI

BiblioSleuth AI is a Calibre plugin that examines selected EPUB package metadata and bounded text from confidently identified title and copyright pages, researches the web with a selected AI and search provider, and proposes metadata for the exact edition. Unidentified pages and chapters are excluded. Nothing is written until you explicitly confirm field-level review or the separately warned bulk-accept workflow.

Author: Terry Trent · Version: 1.1.0 · License: MIT · Minimum Calibre: 7.0.0

BiblioSleuth AI is an independent community plugin and is not affiliated with or endorsed by Calibre or any AI or search provider.

What it can update

Title, authors, series and series index, tags, identifiers (including ISBN and ASIN), publication date, publisher, and comments/description. It does not download books or covers and does not rewrite the EPUB file itself.

Descriptions focus on the book's content and intended audience. ISBNs, local EPUB evidence provenance, publisher/date/format audit notes, and explanations of how an edition was identified are kept in their dedicated metadata fields or the match rationale rather than appended to Calibre comments.

Requirements

  • A supported desktop Calibre installation.
  • At least one selected book with an EPUB format.
  • OpenAI or Anthropic API access, or a running Ollama or LM Studio server.
  • Provider-hosted search for OpenAI/Claude, or a separately running SearXNG service. Ollama and LM Studio require SearXNG.

AI and web-search providers

Select OpenAI, Claude, Ollama, or LM Studio. OpenAI and Claude can use their provider-hosted web search or SearXNG. Claude hosted research uses a cited search request followed by native strict JSON Schema generation because Anthropic does not permit citations and structured output in one request. Full eight-field metadata generation uses two strict calls because Anthropic rejects the complete grammar: the first establishes the edition match and its assigned fields, then the second receives that selected match and returns only the remaining fields. Field-specific requests with four or fewer fields use one generation call. Only bounded, sanitized research text and citation metadata pass between calls; opaque provider search state is discarded. Anthropic receives compact generation grammars containing required keys, types, enums, and nullability; constraints its decoder does not support are omitted there, while the complete canonical schema—including length, count, pattern, range, and URL rules—is enforced locally before review. When Claude is selected it also performs custom-prompt review, repair, synthetic schema testing, connection checks, and final structured metadata generation. Ollama and LM Studio use SearXNG.

OpenAI, Anthropic, Ollama, and LM Studio credentials use separate operating-system vault entries. Environment alternatives are OPENAI_API_KEY, ANTHROPIC_API_KEY, and LM_STUDIO_API_KEY; ANTHROPIC_WORKSPACE_ID supplies the non-secret workspace selector when an Anthropic key requires one. Ollama normally needs no token, but an optional token remains isolated too. Credentials are never copied between providers. The first-run wizard routes local-provider users through full model, endpoint, SearXNG, and readiness-test configuration before research.

Ollama

Install Ollama, pull an instruct model that reliably supports strict JSON Schema output using its documented ollama pull <model> workflow, and keep the API on the default loopback endpoint http://127.0.0.1:11434/v1. Select Ollama, refresh models, and run the connection and capability tests. Model quality and JSON Schema reliability vary.

LM Studio

Use the full LM Studio desktop application's Developer page rather than the Bionic chat surface alone. Download and load a schema-capable, non-thinking instruct model, then start the local server and keep it running throughout research. The LM Studio server root is http://127.0.0.1:1234; BiblioSleuth AI must use the OpenAI-compatible API base http://127.0.0.1:1234/v1. If authentication is enabled, generate a server token and store it in BiblioSleuth AI. Avoid LAN exposure unless it is deliberate and protected. On a memory-limited Mac, start with an 8192-token context and one concurrent prediction.

Avoid thinking/reasoning model variants for LM Studio. Some return the complete JSON result in reasoning_content while leaving the standard content field empty, which is not valid OpenAI-compatible structured output for this integration. Maintainer testing confirmed the workflow with qwen/qwen3-4b-2507; its qwen/qwen3-4b-thinking-2507 counterpart failed in this way. Treat these names as a tested example rather than a permanent quality recommendation.

Local-model quality and hardware

Exact-edition research requires a strong model: it must compare conflicting sources, distinguish similar editions, follow a large structured-output contract, and avoid invented facts and citations. Small models are useful for testing the Ollama or LM Studio connection, but a successful capability test does not mean their research will approach OpenAI or Claude quality. Maintainer testing on an M2 Mac with 16 GB of unified memory found that models practical on that hardware produced substantially weaker results than the supported hosted providers. Larger local models generally require more memory and time, and may still differ in training and research ability. Review every local-model proposal carefully and treat lightweight models as integration tests unless their accuracy has been validated on your own books.

Increase the request timeout for local inference. The first request after loading a model is often slow, and a model close to the computer's memory limit can spend substantial time loading, processing the prompt, generating, or swapping memory. Start around 120 seconds for smaller local models; 180–300 seconds may be necessary for larger models. Persistent memory pressure or repeated timeouts usually means the model is too large for comfortable routine use.

SearXNG

SearXNG is a separate user-managed metasearch service; BiblioSleuth AI does not bundle, install, run, or update it. Follow the official container installation guide, keep it on loopback or HTTPS, and enable JSON results in settings.yml:

search:
  formats:
    - html
    - json

Test http://127.0.0.1:8080/search?q=test&format=json, then enter the base address and select Test SearXNG. BiblioSleuth AI constructs bounded edition searches, filters unsafe URLs, limits snippets/results, and passes the results to the selected AI as untrusted evidence. No MCP package is required. SearXNG has no per-query API fee, but it contacts its configured upstream engines and consumes the user's compute and network resources.

First-run setup

The first toolbar click opens a setup wizard covering workflow, API-key storage, presets, privacy, and toolbar placement. Reopen it with Run Setup Wizard. Settings are organized into General, Optimization, System Prompt, Privacy & Security, and Help tabs.

Long status and preset text wraps inside the settings window, avoiding horizontal scrolling. On the System Prompt tab, View Default Prompt always shows the bundled prompt, while Preview Effective Prompt shows the prompt that research will actually use.

Creating and configuring provider credentials

OpenAI and Claude require separate API keys. Local Ollama normally needs no token; LM Studio needs one only when server authentication is enabled.

  1. Create a key for the selected hosted provider: use OpenAI API keys, or Claude Console → Settings → API keys as described in Anthropic authentication.
  2. In Calibre, open Preferences → Plugins → BiblioSleuth AI → Customize plugin and select that provider.
  3. Paste the matching key into API key. Leave Remember securely enabled to use the operating-system credential vault, then use Test Connection.
  4. Refresh model choices, run the separately disclosed capability test, and save the settings.

You may instead launch Calibre with the provider-specific OPENAI_API_KEY, ANTHROPIC_API_KEY, or LM_STUDIO_API_KEY environment variable. It takes precedence only for that provider. ANTHROPIC_WORKSPACE_ID likewise overrides the saved non-secret workspace selector. BiblioSleuth AI never stores keys in Calibre’s JSON preferences: it uses macOS Keychain, Windows Credential Manager, or Linux Secret Service when available. The workspace ID is not a credential and may be stored in preferences, but is excluded from diagnostics. When a key exists, settings prominently displays ✓ API key is stored securely and active, but never reveals its value. The entry field is labeled Replace API key: leave it blank to keep the active key, type a new value to replace it, or select Delete Stored API Key to remove session and vault copies. If secure storage is disabled or unavailable, the key remains in memory only and must be entered after Calibre restarts. API keys are secrets: do not share them or commit them to source control. Provider references: OpenAI API quickstart and Anthropic authentication.

macOS Keychain integration is tested on macOS. The Windows Credential Manager and Linux Secret Service adapters have automated mock coverage but require field testing on those platforms.

Model choices: the non-editable model dropdown contains provider defaults plus models visible to the configured account or local server. Existing OpenAI choices are preserved when upgrading to provider-aware versions. Claude choices are limited to compatible Opus, Sonnet, Haiku, Fable, and Mythos structured-output families, and effort is sent only to supporting models. Incompatible results do not make an empty catalog appear fresh. If Ollama or LM Studio exposes no model, settings explains how to pull or load one. Each provider’s successful model list is cached separately for seven days and refreshed when stale; use Refresh Model Choices for an immediate refresh. Listing models does not generate text or invoke web search. Model-list APIs do not report every required capability, so use the separately confirmed, potentially billable Test Model Capabilities… action before selecting an unfamiliar model. Changing provider or model requires any custom prompt to be validated again against that runtime.

Basic workflow

  1. Select one or several books and click the main BiblioSleuth AI icon.
  2. For batches, review eligible EPUBs, skipped books, cache behavior, preset, and rough estimate in preflight. The prompt does not read or hash complete EPUB files, so it remains responsive for large selections.
  3. Monitor fingerprinting, exact cache detection, EPUB reading, research, and completion stages in Jobs.
  4. When research completes, a persistent non-modal notice offers Review books, Accept all…, Hide notification, or Abort. It never opens review automatically or blocks other Calibre work.
  5. Hiding keeps results available; click the numbered BiblioSleuth AI toolbar icon later. Abort discards all waiting results without changing metadata.
  6. Review changed/unchanged typography, confidence badges, inference labels, usage, and categorized evidence sources. The table follows Calibre’s palette for readable light and dark themes.
  7. Use Select recommended, Select none, Restore AI proposal, or View all details…. Correct any field before applying it.
  8. Descriptions offer rendered and HTML-source views with counts; tags use an add/remove editor.
  9. Navigate with Review previous book, Skip this book and review next, and Approve selected fields and review next (or the corresponding “finish” label on the last book). Nothing is written until final confirmation.

Research only selected fields: open the arrow beside the BiblioSleuth AI icon and choose Research Specific Fields…. Select Title, Authors, Series, Tags, Identifiers, Published Date, Publisher, and/or Description. Only checked fields are sent as the requested output contract and only those fields appear in review. Series and series index are one choice, so requesting Series always researches the book number too. The main icon continues to research every supported field.

Blind accept: choose Accept all… in the notice or Accept All Pending Results… in the toolbar menu to skip every review screen. The confirmation reports book, inferred-field, and low-confidence-field counts. Confirming applies every non-null proposal, verifies that records and EPUBs have not changed, and creates one undo checkpoint. AI output can be wrong; this deliberately bypasses field-level review and should be used only when that risk is acceptable.

Once review has started, Accept all remaining books… performs the same confirmed operation for the current book and every later book, preserving proposal edits already made. Navigation labels state the result explicitly: Review previous book, Skip this book and review next, and Approve selected fields and review next; the final book uses “finish” instead. These controls share one aligned horizontal row.

Review shortcuts: Space toggles a field, Enter edits it, Ctrl+Shift+A selects recommended values, and Ctrl+Return applies and advances. Undo Last BiblioSleuth AI Changes restores the last batch during the same session; keep normal Calibre backups.

After applying changes, the complete update count and provider-aware usage/cost estimate appear in a resizable, scrollable completion window. Select the text directly or use Copy summary.

Performance statistics

Choose Statistics… from the toolbar arrow or the Statistics configuration tab. The Overview reports researched, successful, failed, cancelled, applied, skipped, and discarded counts; live/cache counts; total retrieval time; average, median, fastest, slowest, P90, P95, and books per minute.

The timing breakdown reports average queue wait, fingerprinting, cache lookup, EPUB extraction, provider request, application-managed search, response validation, review wait, and metadata normalization/application. Filter or group by AI provider and search provider; hosted and SearXNG search calls are counted separately.

Usage reports input/cached/output/reasoning/total tokens, searches, total and average estimated cost, tokens and cost per successful record, and estimated avoided cost when a session-cache result retains its original lookup cost. SearXNG calls never receive a hosted-search fee. When selected records mix known and unavailable provider costs, Statistics reports the coverage and does not present a partial subtotal as the total. Costs are planning estimates, not invoices.

The Comparisons tab groups by optimization preset, model, live/cache source, outcome, date, or single-book/batch operation. Filters cover Session, 7, 30, 90 days, or All plus model, preset, source, and outcome. Filtered data can be exported as anonymized CSV; all history can be cleared.

Collection is enabled by default and retains no more than 1,000 records or 90 days, whichever limit is reached first. The Statistics settings tab can disable new collection or change both limits. Disabling collection preserves existing history until it is cleared.

Each record contains only timestamps, a salted truncated EPUB fingerprint, AI/search provider, model/preset/research limits, timings, cache state, token/search usage, estimated cost, outcome category, and batch size. Pre-provider failures and unstarted cancellations are recorded as known-zero cost; unavailable provider pricing remains unknown. Diagnostic history retains the same provider/search provenance and separate hosted/SearXNG counters. It never contains titles, authors, library IDs, paths, EPUB content, prompts, responses, evidence URLs, API keys, or exact errors.

Cancel a running research job from Calibre’s Jobs panel. Cancellation takes effect after the current network request returns; any books already researched are still offered for review.

The progress bar advances as each EPUB is read and each book’s research finishes. While an AI provider or SearXNG is processing an individual request, the percentage may remain unchanged because these APIs do not expose continuous per-request progress. Cancelling stops additional SearXNG queries and avoids starting a model request when possible; a network request already in progress can take until its response or configured timeout. If that response completes after cancellation, its result is discarded but its usage, cost, search counts, and timing remain in Statistics for the interrupted book. Only books never started are recorded as zero-cost cancellations. A job with no reviewable results shows a retained non-modal completion notice instead of entering the pending-review queue.

Successful results are cached in memory for the current Calibre session using the EPUB fingerprint, provider, model, endpoint and remote-endpoint policy, search path, effective prompt, requested-field set, and research settings. Changing a local endpoint cannot reuse a result from another server. An identical repeat avoids a new billable request but still opens review. Full and field-specific lookups never share a cache entry unless their requested fields are identical. Cached reviews show research time and model. Use Research fresh… in review or Research Fresh (Ignore Cache) in the toolbar menu to replace it, or Clear Session Lookup Cache to remove all cached lookups. The cache disappears when Calibre exits.

Requesting fewer fields can reduce structured-output tokens, particularly when Description or Tags is omitted. Exact-edition identification and web research remain active, so search calls, input tokens, time, and cost may not decrease proportionally.

Expected token and search usage

These are planning estimates, not a quota or price guarantee. Actual usage depends on available title/copyright-page evidence, the selected model, search context, source pages, and model behavior.

Default-provider cost comparison: OpenAI with GPT-5.6 Luna is substantially cheaper than Claude Sonnet 5 for this workflow. Maintainer testing of complete Balanced hosted-search lookups observed approximately $0.07 per book with OpenAI versus nearly $0.13 with Claude. This is an observed planning example, not a promised rate or an equal-capability benchmark. Claude has higher model-token rates and, for a full record, uses a separate search request plus two strict generation calls; OpenAI normally completes hosted research and generation in one Responses API request.

Maintainer-observed quality and cost order

  1. OpenAI with OpenAI hosted search: best overall results; second-lowest API cost among the four tested hosted-model paths.
  2. OpenAI with SearXNG: lowest tested API cost; results were nearly as good as OpenAI hosted search.
  3. Claude with Claude hosted search: results were on par with OpenAI; highest tested API cost.
  4. Claude with SearXNG: results were on par with OpenAI plus SearXNG; third-lowest tested API cost.
  5. LM Studio with SearXNG: model-dependent; qwen/qwen3-4b-2507 produced acceptable results on the maintainer's M2 Mac.
  6. Ollama with SearXNG: model-dependent; the tested LM Studio Qwen 3 4B path produced better results than Ollama with gemma3:4b and qwen3:8b.

This is a small-sample maintainer observation, not a permanent benchmark or guarantee. Results can change with the book, model revision, search output, prompt, and hardware. Cost ranks compare only the four OpenAI/Claude paths. Local inference has no per-request model API fee, but it still consumes hardware, power, time, and maintenance effort.

Configuration reference

  • Model: OpenAI defaults to gpt-5.6-luna and Claude defaults to claude-sonnet-5. Current supported Claude models are available immediately; Refresh Models adds compatible account-visible models. Ollama and LM Studio list models exposed by the local server. Any selection must reliably support the provider’s required strict structured-output behavior.
  • Claude workspace ID: Multi-workspace or identity-linked Anthropic keys require the wrkspc_… ID from Claude Console → Settings → Workspaces. Single-workspace keys can leave this blank. ANTHROPIC_WORKSPACE_ID takes precedence when set.
  • Test Model Capabilities: makes a clearly disclosed billable structured-output request with web search and checks the required features.
  • Maximum searches per book: limits edition-oriented SearXNG queries (1–10, default 3). It does not affect provider-hosted search.
  • Results per search: limits sanitized SearXNG results supplied to the model per query (1–10, default 6). More results increase model input and can add noise.
  • Timeout: maximum wait for an API request (10–300 seconds, default 60). Local models commonly need at least 120 seconds; larger or memory-constrained models may need 180–300 seconds, especially on their first request after loading.
  • Optimization preset: Balanced is the default. Economy allows 4,000 title/copyright-page evidence characters, low search context, no reasoning, a 1,600-token output cap, and up to 2 evidence URLs per field. Balanced allows 6,000 characters, low search context, low reasoning, a 2,000-token cap, and up to 3 URLs. Thorough allows 12,000 characters, medium search context, medium reasoning, a 3,000-token cap, and up to 4 URLs. Custom unlocks all five controls.
  • Web search context: low reduces search context/cost; high may improve difficult edition matching.
  • Title/copyright evidence characters: maximum combined text disclosed from confidently identified title and copyright pages.
  • Reasoning effort: controls supported OpenAI and Claude models under Custom optimization. It is disabled for Ollama, where BiblioSleuth AI requests no reasoning for structured-output reliability, and for LM Studio, where reasoning is controlled by the loaded model. Use a non-thinking LM Studio instruct model.
  • Maximum output tokens: caps reasoning plus final structured metadata output. A cap that is too low can prevent a complete schema response. Claude hosted search uses a separate 6,000-token safety ceiling because Anthropic counts intermediate server-search turns against that request’s output budget; its prompt still requests a concise evidence summary.
  • Maximum evidence URLs per field: controls how many of the strongest direct sources each proposed field may return.
  • Maximum tags: limits the normalized tags written to Calibre (1–100, default 20).
  • Maximum description characters: limits the sanitized description written to Calibre (500–30,000, default 5,000). These two limits are independent of the optimization preset.
  • System prompt override: changes research guidance. Custom prompts must pass AI review and a synthetic schema test before saving.
  • Statistics: enables anonymized performance collection and configures retention days and maximum records.

BiblioSleuth AI identifies title and copyright pages using EPUB guide and structural semantics, filenames, spine position, and conservative bibliographic markers. It sends at most one page for each purpose. If a page cannot be identified confidently, it is omitted instead of substituting other early pages. It uses a stable prompt-cache key and reports input, cached-input, output, reasoning, total-token, and web-search usage after each job. The selected evidence-URL limit is enforced in the response schema and again during local validation.

Each book’s review window and full-details view show that lookup’s token usage, web-search count, and estimated USD cost. The final message and job log show totals for the batch. Cost is estimated from reported tokens, cached tokens, output tokens, and web-search calls using a bundled standard-pricing table dated in the display. It is not an invoice and may exclude account-specific discounts, taxes, regional processing, service-tier adjustments, or later price changes. When the selected model is absent from the bundled pricing table, BiblioSleuth AI reports tokens but does not guess a cost.

Privacy and data handling

BiblioSleuth AI sends selected OPF metadata and only the configured amount of text from confidently identified title and copyright pages. It never sends unidentified pages, contents, prefaces, introductions, dedications, or body chapters, and it never uploads the complete book. When neither page can be identified confidently, only selected OPF fields are sent. Web pages, SearXNG results, and EPUB text are treated as untrusted evidence. Review the selected provider's current API data controls before use.

EPUB archive members are read through strict decompression and size limits. A simple legacy external DOCTYPE in package XML is stripped without being resolved; bundled defusedxml independently rejects DTDs, entity declarations, and external references. Instruction-like text in included evidence triggers a warning and prevents fields from being preselected. Model-provided evidence links require confirmation before opening. Generated comments are reduced to a small formatting allowlist; links, images, scripts, styles, forms, SVG, embedded media, and attributes are removed.

BiblioSleuth AI keeps provider credentials separate and refuses unsafe endpoint forms and redirects. Plain HTTP local-model and SearXNG access is restricted to loopback by default; use HTTPS for remote services. Selecting SearXNG sends bounded queries to that instance and its upstream search engines even when inference is local.

Confidence, evidence, and editions

BiblioSleuth AI prioritizes exact identifiers, then publisher/edition/date agreement, then title and authors. Evidence links show why a value was proposed. “Inferred” means the value was synthesized rather than directly stated. AI and web sources can be wrong; review identifiers, series order, dates, and publisher especially carefully.

Failures and troubleshooting

  • API key required: configure the selected hosted provider's key.
  • SearXNG unavailable: confirm the service is running and JSON search is enabled.
  • 401/403: check provider or local-server authentication.
  • 429: a provider or upstream search-engine limit was reached.
  • Model unavailable: load or select a model supporting reliable structured output.
  • No EPUB: add an EPUB format to the selected Calibre record.
  • Incorrect match: inspect evidence, edit proposed values, or skip the record.
  • Toolbar icon/action missing: restart Calibre, then add BiblioSleuth AI under Preferences → Toolbars & menus.

Failure results provide direct Configure, Retry failed fresh, and Troubleshooting actions. Job logs stay generic while the completion dialog provides useful guidance.

Diagnostics and support privacy

Copy Redacted Diagnostics is available in the toolbar menu and Help settings tab. It includes versions, platform, preset, model name, non-secret limits, prompt version/hash and validation state, credential source, and cache size. It excludes API keys, headers, EPUB text, library metadata, full custom prompts, responses, and evidence URLs. Review clipboard contents before sharing.

Failure dialogs also provide Collect diagnostic logs…; after closing one, use Collect Recent Diagnostic Logs… from the toolbar arrow. A bounded local journal retains at most 20 job summaries for seven days. Successful jobs keep minimal stage/timing/usage counts. Failures additionally retain sanitized category/stage, optional sanitized message and stack, salted anonymous book identity, and content-free EPUB structure such as member/byte/encryption counts and container declaration flags.

A preview explains the four ZIP files before saving: README, manifest, redacted environment/configuration with aggregate statistics, and recent journal. Choose whether to include detailed sanitized errors/stacks and where to save, or clear retained diagnostic history. Nothing is uploaded automatically.

Diagnostic history and bundles never contain API keys or authorization headers, titles, authors, library IDs or paths, EPUB text or metadata values, full prompts, model responses, evidence URLs, credential-vault data, or unredacted URLs. Review the resulting ZIP before sharing it.

Safety and limitations

Changes affect Calibre’s library metadata, not embedded EPUB metadata. Identifiers are merged by type rather than replacing the entire identifier set. Small batches are supported, but unattended bulk processing is not. Search availability, sites, model output, pricing, and rate limits are outside the plugin’s control. Keep library backups and review every proposed change.

Updating and uninstalling

Restart Calibre after installing or updating BiblioSleuth AI. To uninstall, open Preferences → Plugins, select BiblioSleuth AI under User interface action plugins, and choose Remove plugin. Uninstalling does not reverse metadata already applied and does not modify EPUB files. Select Delete Stored API Key before uninstalling if you also want to remove the operating-system credential-vault entry, and Clear Statistics… if you want to delete retained performance history.

Getting support

When reporting a problem, provide the BiblioSleuth AI version, Calibre version, operating system, optimization preset, and a redacted error from the Jobs panel. Never post an API key, complete custom prompt, copyrighted EPUB passage, or private library export. The source distribution includes a security policy and version history.
